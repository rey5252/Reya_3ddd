# RA3 Texture Studio: дизайн

Дата: 2026-10-15
Статус: погоджено в чаті (архітектура та функції), очікує перегляду спеку

## Мета

Браузерна програма для створення скінів юнітів і будівель для Command & Conquer: Red Alert 3 (2008).
Вона дає готовий для Mod SDK набір файлів `Назва.dds`, `Назва_NRM.dds` і `Назва_SPM.dds`.
Скін можна зробити трьома способами, у будь-якому поєднанні:

- процедурними шарами (панелі, заклепки, камуфляж, іржа…), без малювання;
- з власного зображення (PNG/JPG/TGA), до якого програма доробить NRM і SPM;
- з уже витягнутих текстур гри (DDS), щоб їх перефарбувати й доредагувати.

**Критерій успіху:** користувач відкриває `index.html` подвійним кліком (без інтернету й без встановлення),
за кілька хвилин отримує три DDS з mip-рівнями, і вони виглядають у грі так само, як у прев'ю програми.

## Що сказав користувач і що ми припустили

Сказав користувач:
- текстури саме для скінів юнітів і будівель;
- програма має працювати в браузері;
- джерело зображення не принципове, тому підтримуємо всі три;
- погодив архітектуру «чистий JS без залежностей» і список функцій.

Припущення (можна виправити):
- інтерфейс українською;
- програма лежить у репозиторії в папці `ra3texture/` поруч із модами Minecraft;
- нормалі за замовчуванням у конвенції DirectX (зелений = −Y), бо арт RA3 готувався в 3ds Max під DX9.
  Є перемикач «Інвертувати Y».

## Формат текстур RA3 (з офіційних шейдерів EA)

Джерело: `electronicarts/CnC_Modding_Support`, `Red Alert 3/Shaders/Objects.fxh`, `Gamma.fxh`, `Common.fxh`,
`Xml/GlobalData/MultiplayerColors.xml`.

| Файл | Канали | Як використовує гра |
|---|---|---|
| `Назва.dds` (DiffuseTexture) | RGB = колір (гамма 2.2), A = прозорість | Alpha-test з порогом `0x60` (96) |
| `Назва_NRM.dds` (NormalMap) | RGB = нормаль у дотичному просторі | `n = tex*2−1`, потім `n.xy *= BumpScale` (1.5 для фракцій) |
| `Назва_SPM.dds` (SpecMap) | R = блиск, G = не використовується, B = колір гравця, A = не використовується | див. нижче |

Формули шейдера:

```
diffuse  = lerp(tex.rgb, tex.rgb * RecolorColor * 2, spm.b)   // у гамма-просторі
diffuse  = pow(diffuse, 2.2)                                  // GammaToLinear
color    = ambient*diffuse + Σ sun*diffuse*max(0, N·L) + env(reflect) * sunColor * spm.r
```

`RecolorColor` — колір гравця з `MultiplayerColors.xml` (0..1). Множник ×2 означає, що сірий 50% у масці
дає рівно колір гравця, а світліші ділянки дають світліший відтінок.

Кольори гравців для прев'ю (RGB): Gold 240,215,25 · Red 230,20,20 · Blue 50,75,200 · Green 20,105,60 ·
Orange 225,115,20 · SkyBlue 102,207,248 · Purple 125,25,200 · Pink 248,152,248.

## Архітектура

Чистий JavaScript без залежностей і без збірки. Скрипти підключаються звичайними `<script>`
(не ES-модулі, бо модулі не вантажаться з `file://`). Кожен файл ядра експортує простір імен
`RA3.<модуль>` у браузері та `module.exports` у Node, тож його можна тестувати через `node --test`.

```
ra3texture/
  index.html          розмітка інтерфейсу
  style.css           стилі (темна тема, «військовий» вигляд)
  js/util.js          RNG за seed, шум (value/fbm), математика кольору, ресемплінг
  js/dds.js           читання/запис DDS: DXT1, DXT5, A8R8G8B8 + mip-рівні
  js/tga.js           читання TGA (24/32-біт, нестиснений і RLE)
  js/maps.js          модель документа, накладання пензля, збирання NRM/SPM, прев'ю 2D
  js/generators.js    процедурні шари
  js/preview3d.js     WebGL-прев'ю з формулою шейдера RA3
  js/project.js       збереження/відкриття проєкту (.json)
  js/app.js           зв'язок UI з ядром (єдиний файл, що чіпає DOM, окрім preview3d)
  test/*.test.js      тести ядра (node --test)
  js/meshes.js        процедурні моделі для 3D-прев'ю (чисті функції, тестуються в Node)
  test/smoke.cjs      smoke-тест сторінки в Chromium (Playwright)
  README.md           інструкція українською
```

Залежності між модулями: `util` ← `dds`, `tga`, `maps`, `generators`; `maps` ← `generators`, `project`;
`app` ← усе. `preview3d` залежить лише від WebGL і отримує готові буфери RGBA.

## Модель документа (`maps.js`)

- Розмір `size × size`, де `size ∈ {256, 512, 1024, 2048}` (за замовчуванням 512). Назва скіна, наприклад `AUMyTank`.
- П'ять внутрішніх карт:
  - `color`: Uint8ClampedArray RGBA (A = прозорість);
  - `height`: Float32Array 0..1 (0.5 = рівно);
  - `spec`: Uint8 0..255;
  - `team`: Uint8 0..255;
  - `nrmImport`: необов'язкова імпортована NRM, RGB.
- **Конвеєр перебудови:** беремо базу (колір 128,128,128,255; висота 0.5; блиск 0; колір гравця 0), застосовуємо
  ввімкнені шари по порядку, а потім **оверлеї пензля**. Для кожної цілі (колір, прозорість, висота,
  блиск, колір гравця) оверлей має значення й покриття 0..1, і `результат = lerp(шари, оверлей, покриття)`.
  Тому мазки пензля переживають зміну параметрів шарів.
- **NRM:** Собель по висоті із загортанням країв (текстура тайлиться, `AddressU/V = Wrap`) і силою 0..10.
  `n = normalize(−dx·s, −dy·s, 1)` у координатах зображення (y донизу). Для DirectX `G = 0.5 + 0.5·n.y`,
  для OpenGL `G = 0.5 − 0.5·n.y`. Якщо є `nrmImport`, результат змішується за схемою whiteout:
  `normalize(a.xy + b.xy, a.z·b.z)`.
- **SPM:** `R = spec`, `G = 0`, `B = team`, `A = 255`.
- **Вигляд у грі (2D):** формула шейдера з вибраним кольором гравця та простим освітленням
  (сонце зверху-зліва + відбиття неба за блиском).

## Процедурні шари (`generators.js`)

Кожен шар має тип, назву, `enabled`, `seed` і параметри. Функція `apply(doc, params, seed)` змінює карти
документа. Результат детермінований за seed. Шари:

| Шар | Параметри | Що змінює |
|---|---|---|
| Основа фракції | пресет (Альянс / СРСР / Імперія / свій колір), шум | колір, трохи блиску |
| Камуфляж | тип (плями / смуги / цифровий), 2–3 кольори, масштаб, покриття | колір |
| Панелі | кількість по X/Y, розкид, ширина шва, глибина | висота (шви вниз), колір (шви темніші), блиск по краю |
| Заклепки | крок, розмір, уздовж швів або сіткою | висота (купол), блиск |
| Бруд/пил | сила, градієнт знизу, масштаб шуму, колір | колір (затемнення), блиск ↓ |
| Іржа | кількість, розмір плям, колір | колір, висота (шорсткість), блиск → 0 |
| Подряпини | кількість, довжина, ширина | колір (світлий метал), блиск ↑, висота ↓ |
| Колір гравця | режим (смуги / прямокутник / за яскравістю), розміщення, сила | team, колір → нейтральний сірий під маскою |
| Зображення | імпортований файл, ціль (колір / висота / блиск / колір гравця / прозорість), канал-джерело для одноканальних цілей (яскравість / R / G / B / A), непрозорість | обрана карта |

Пресети фракцій (базові кольори):
- Альянс: світло-сірий синюватий `#9fa9b0` та темний `#4a5560`;
- СРСР: червоно-коричневий `#7a2e24` та сталевий `#4b4a45`;
- Імперія: білий слоновий `#d8d4c8` та графітовий `#2f3236`.

## Пензель і редагування (`app.js` + `maps.js`)

- Ціль: колір, прозорість, висота, блиск або колір гравця. Параметри: розмір, м'якість, сила, значення/колір. Є гумка (зменшує покриття оверлею).
- Пензель також тайлиться, тобто мазок біля краю продовжується з протилежного боку.
- Undo/Redo (Ctrl+Z / Ctrl+Y) для мазків: до 30 знімків оверлеїв.
- Оверлеї зберігаються 8-бітно (значення й покриття 0..255), тож проєкт зберігається без втрат.

## Імпорт

- PNG/JPG/WebP браузер декодує сам. TGA читає `tga.js`, DDS читає `dds.js` (DXT1 разом з 1-бітною альфою, DXT3,
  DXT5, A8R8G8B8/X8R8G8B8 з будь-якими масками, 24-біт RGB). Інші формати дають зрозуміле повідомлення.
- Імпорт стає шаром «Зображення» і масштабується до розміру документа (білінійно).
- **Набір з гри:** якщо перетягнути кілька файлів, їх розкладено за суфіксами:
  - `*_NRM` → `nrmImport`;
  - `*_SPM` → два шари «Зображення» (канал R → блиск, канал B → колір гравця);
  - решта → колір і прозорість.
  Назва скіна береться з імені файлу.

## Експорт (`dds.js`)

- Повний ланцюжок mip-рівнів, box-фільтр 2×2. Для NRM після даунсемплу вектор перенормалізується.
- Формати за замовчуванням:
  - колір у DXT1, а якщо є альфа < 255, то в DXT5;
  - NRM і SPM у DXT1.
  Перемикач «Без стиснення» дає A8R8G8B8 для всіх трьох.
- DXT-кодер: для кожного блоку 4×4 кінцеві точки шукаються вздовж головної осі (PCA, степеневий метод) з інсетом.
  DXT1 у 4-кольоровому режимі (`c0 > c1`), DXT5 з 8-рівневою альфою.
- Заголовок DDS: 128 байт; `DDSD_CAPS|HEIGHT|WIDTH|PIXELFORMAT|MIPMAPCOUNT|LINEARSIZE`,
  `DDSCAPS_TEXTURE|MIPMAP|COMPLEX`.
- Також можна експортувати PNG усіх трьох карт.
- Кодування 2048² йде шматками через `setTimeout` з індикатором прогресу, щоб сторінка не зависала.
  Web Worker не використовуємо, бо він не працює з `file://` у Chromium.
- Файли віддаються як завантаження (`a[download]`).

## Проєкт (`project.js`)

`.json` з версією формату, розміром, назвою, списком шарів (тип, параметри, seed, enabled), імпортованими
зображеннями та оверлеями пензля (сирі байти, стиснені deflate через `CompressionStream`, у base64; працює і в браузері, і в Node для тестів). Відкриття відтворює ті самі карти, що й до збереження.

## 3D-прев'ю (`preview3d.js`)

- WebGL 1. Моделі: куб, циліндр, сфера і «танк» (корпус, башта й ствол із примітивів), з UV на кожну грань.
- Фрагментний шейдер повторює формулу RA3: recolor у гамма-просторі, `pow 2.2`, ламберт від сонця, ambient,
  відбиття неба (градієнт + сонячна пляма) × `spm.r` × 0.8. Нормалі беруться з NRM з `BumpScale = 1.5`.
  Відсікання за альфою `< 96/255`. Наприкінці `pow(1/2.2)`.
- Обертання мишею, автообертання, вибір кольору гравця (8 кольорів гри).
- Якщо WebGL недоступний, показуємо повідомлення, а 2D-прев'ю працює далі.

## Інтерфейс

Три колонки:
- **ліва**: шари (список з галочками, ↑↓, видалити, «+ шар») і параметри вибраного шару;
- **центр**: полотно з вкладками «Колір · Висота · NRM · SPM · Прозорість · У грі» та інструментами пензля;
- **права**: 3D-прев'ю, колір гравця, налаштування документа (назва, розмір, сила NRM, інверсія Y),
  кнопки «Імпорт», «Експорт DDS», «Експорт PNG», «Зберегти/Відкрити проєкт».

Можна перетягнути файли на сторінку. Під час першого запуску відкривається демо-скін (основа Альянсу, панелі, заклепки, бруд,
смуга кольору гравця), щоб одразу було видно, як усе працює.

## Обробка помилок

- Непідтримуваний DDS/TGA або пошкоджений файл: повідомлення в рядку стану, документ не змінюється.
- Неквадратне зображення чи розмір не степінь двійки при імпорті: масштабування до розміру документа.
- Зміна розміру документа: перерахунок шарів, а оверлеї й імпорти перемасштабовуються.
- Не вдалося відкрити проєкт (інша версія чи пошкоджений JSON): повідомлення, поточна робота не губиться.

## Тестування

`node --test ra3texture/test/`:
- `dds`: заголовок (magic, розміри, mipCount, fourCC), розмір даних для кожного mip-рівня, encode→decode суцільного кольору
  точний (з урахуванням 565), для градієнта середня похибка ≤ 8/255, DXT5-альфа, читання A8R8G8B8 і DXT3;
- `tga`: нестиснений і RLE, орієнтація (біт origin);
- `maps`: рівна висота дає NRM (128,128,255), нахил у правильний бік для DirectX/OpenGL, пакування SPM,
  оверлей (покриття 0/1), загортання пензля, mip-перенормалізація NRM;
- `generators`: однаковий seed дає однаковий результат, різний seed дає різний, кожен шар змінює саме свої карти;
- `project`: зберегти→відкрити дає ідентичні карти.

`test/smoke.cjs` (Playwright, вбудований Chromium) відкриває `index.html` через `file://`, чекає демо-скін, натискає
«Експорт DDS» і перевіряє, що завантажилися три файли з правильними іменами й magic `DDS `, а в консолі немає помилок.

CI: окремий job `ra3texture` у `.github/workflows/build.yml` запускає `node --test` (Node 20). Збірку модів це не зачіпає.
